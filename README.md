# 拾惠 · 返利管理

React / TypeScript 管理后台，NestJS API，Prisma / PostgreSQL 持久存储。**已移除演示登录和内存示例记录**。没有真实平台数据时，列表为空、统计为 0；未知价格或收益显示“待确认”。

## 本机使用

后台：<http://127.0.0.1:5173>。首次进入页面创建管理员用户名和密码（非空即可，无字符组合要求），完成后初始化入口自动关闭。之后使用用户名和密码登录；在 **系统设置 → 账户安全** 修改密码，旧会话立即失效。

1. **联盟配置**：在后台填写 AppKey、AppSecret、联盟 ID、网站 / APP ID、推广位 ID，保存后测试。
2. **渠道管理**：在后台填写 CorpID、AgentID、Secret、回调 Token、EncodingAESKey、管理员通知 UserID。
3. 密钥 AES-256-GCM 加密入库；接口只返回是否已配置，不返回明文。编辑时密钥留空会保留原值。
4. 保存新配置后，旧测试结果清除。测试成功仅说明被测试的接口通过，不代表全部权限或回调可用。
5. **订单管理**：独立展示商品信息、来源、金额、付款金额、预计返现、返现比例、下单时间、完成时间、订单号、状态。时间为北京时间，精确到秒。支持已完成 / 待付款 / 已取消筛选，未知状态保持待核实；已付款不冒充待付款或已完成。

## 本地开发

推荐 Node.js 22.12+ 与 Docker Desktop。先启动 Docker Desktop，然后只需一条命令：

```sh
npm run dev
```

它会依次完成：首次安装依赖 → 首次生成 `.env`（随机密钥，不覆盖已有配置）→ 启动本地 PostgreSQL 容器（仅暴露 `127.0.0.1:54329`，数据存入专用 Docker 卷）→ Prisma 生成与迁移 → 同时启动 API（3001）和后台（5173，热更新）。`Ctrl+C` 停止前后端，数据库容器继续在后台运行；`npm run db:stop` 停止数据库（数据保留）。只想单独启动前后端可用 `npm run dev:apps`。

API 健康检查：<http://127.0.0.1:3001/api/v1/health>，Swagger：<http://127.0.0.1:3001/api/docs>。

## 当前真实接入能力与边界

- 登录通过数据库密码哈希验证；角色来自数据库，不可在登录时自行选择。财务角色禁止修改平台凭证及规则。
- 统计、用户、订单、转链记录、资金流水、提现、配置和审计查询均使用 PostgreSQL。
- 京东转链、商品信息查询、订单权限测试和分时段历史订单查询会实际请求官方网关；失败返回错误，绝不返回固定商品或原始链接作为成功结果。
- 京东另有第三方接入「京东联盟 · 喵有券」（ecapi.cn），在联盟配置单独填写并用开关启用：启用后京东链接改由喵有券查券转链，订单同步仍走官方接口。说明见 [平台插件说明](docs/platform-plugins.md#京东第三方接入喵有券)。
- 淘宝订单数据源可选：官方账号授权（taobao.tbk.sc.order.details.get，后台发起淘宝 OAuth 授权，凭证加密保存）、官方推广者、喵有券，明确选择、不自动切换，说明见 [平台插件说明](docs/platform-plugins.md#淘宝订单同步)。
- 淘宝另有第三方接入「淘宝联盟 · 喵有券」，开关启用后走喵有券解析商品 + 官方查价转链的混合流程，说明见 [平台插件说明](docs/platform-plugins.md#淘宝第三方接入喵有券--官方混合)。
- 企业微信支持 GET 回调验证、POST 验签/AES 解密、接收企业/应用校验、时间窗与消息去重，回调入库后异步处理；后台轮询持久化 Inbox，最多 5 次重试。当前不是 BullMQ 集群队列。
- 支持真实身份的 `/帮助`、`/余额`、`/订单`、`/提现记录` 与商品链接回复。
- 提现审核/拒绝/确认人工打款使用 PostgreSQL Serializable 事务、版本检查、唯一资金流水和审计；系统不自动打款。
- **尚未完成真实账户端到端联调**。需要你在后台保存有效凭证并配置公网 HTTPS 回调、应用可见范围与可信 IP。
- **订单归属、状态映射、结算口径尚待实际京东账户验证**。导入订单保留原始状态并进入待核实，不自动给用户发钱。计佣金额不冒充订单原价/实付金额，未知字段为空。商品优惠券、预计返现和到手价未经确认不计算。
- 用户 `/提现` 申请尚未开放，收款资料、归属核验与入账链路完成后才能启用。订单通知 Outbox、定时补偿同步、退款冲正与完整细粒度 RBAC 仍需后续实现。
- 淘宝、拼多多仅预留来源显示与适配器接口，未实现这些平台业务。

## 验证

```sh
npm run build
npm test
npm run test:api
```

`test:api` 在 PostgreSQL 创建随机 `test_*` 隔离 Schema 和本机 3107 端口服务，测试完成只清理该 Schema。它不会向正式库注入商品、订单或测试密钥，也不会调用真实第三方服务。覆盖加密脱敏、持久化、角色权限、订单字段和并发打款幂等。

## Docker

```sh
docker compose up --build -d --wait
```

前端与 API 打包为单个镜像（NestJS 同时提供后台页面），独立容器栈入口绑定本机 8081，数据库不暴露端口。容器使用自己的 PostgreSQL 数据卷，不与本机开发栈共享。部署至公网前配置 TLS。`JWT_SECRET` 与 `CONFIG_ENCRYPTION_KEY` 可不配置，首次启动自动生成并保存在 `/app/data/secrets.json`（`appdata` 卷）。备份 PostgreSQL 和该卷（或 `CONFIG_ENCRYPTION_KEY`）；丢失加密主密钥将无法读取已保存的平台凭证。NAS 镜像导入、部署、更新与备份步骤见 [NAS 部署说明](deploy/nas/README.md)。NAS 默认端口 8081，避免与 tg-vault 冲突。推送到 main 时 GitHub Actions 依次执行 verify → build（amd64 / arm64 原生构建）→ push，发布 `sunqz/shop-cashback` 多架构镜像；服务器可直接使用 [deploy/docker-compose.yml](deploy/docker-compose.yml) 拉取部署。挂载 `/var/run/docker.sock` 后可在后台「系统设置 → 版本更新」一键更新（等同于授予容器宿主机 Docker 控制权，不需要时去掉该挂载或设置 `UPDATE_ENABLED=false`）。

架构与 API 见 [说明](docs/architecture.md)，测试范围见 [验证记录](docs/verification.md)。
